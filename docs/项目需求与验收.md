# IT 服务台项目协同工作台：需求与验收

## 项目定位
个人实践与本地演示原型，用于验证 IT 支持流程和 AI 辅助分诊。没有真实企业使用、生产上线或效率提升证据。本文由当前代码和本轮验收整理，不代表此前已经开展企业需求调研。

## 用户与问题假设
员工需要描述问题、提交工单；服务台人员需要确认分类、影响程度与处理人；工程师需要推进处理并回查状态；项目跟进者需要查看任务依赖、风险和进展。以上是场景假设，尚未经过真实用户访谈验证。

## 首期范围与规则
1. 输入问题→DeepSeek 分类及优先级建议→人工确认→带入工单草稿→确认申请人后提交。建议不会自动派单或代替人工判断。
2. 工单状态按 OPEN→ASSIGNED→IN_PROGRESS→RESOLVED→CLOSED 推进，页面先选择工程师，并回查状态记录。
3. 前置任务未完成时禁止后续任务进入进行中或完成；任务包含负责人、日期、优先级和里程碑。
4. 风险登记、处理中、关闭与回查；进展快照汇总累计完成、进行中、阻塞、逾期和未关闭风险，不声称本周新增完成量。
5. 反馈保存原建议、人工最终分类、动作与时间；最近 50 条可查询，旧记录缺失信息不补造。
6. DeepSeek 未配置或请求失败时使用规则降级并标注原因；演示知识条目来自本地静态库，不是 RAG 或企业知识库。

## 已执行验收及证据
- 用户逐项确认：任务依赖阻止与解除、风险新增和状态保存、关闭风险回查、进展统计和复制、工单完整关闭与记录回查、AI 建议到建单、反馈记录查询。
- 五条虚构模型案例首测 4/5，明确“信息不足的故障默认中优先级”后全量复测 5/5。记录见根目录 deepseek-acceptance-results.json 和 deepseek-acceptance-retest.json。该结果不代表整体准确率或长期稳定性。
- 自动化测试：8 类模型异常与反馈纠正、23 项已有工单测试，共 32 项通过。异常由模拟响应验证，不是实际导致服务故障。
- 本轮新增：进展快照纳入未关闭风险，名称与累计统计口径统一；需单独完成渲染验证。

## JD 对应与证据边界
- 业务需求与产品方案：有流程、状态和异常规则；缺真实调研与需求优先级讨论。
- 文档沉淀：有本次整理的需求、验收和限制材料；不能声称此前写过企业 PRD 或参加正式评审。
- 问题反馈与验证：有用户验收发现问题、修复及复测记录；只有本地验证，没有生产上线。
- AI 工具与内部系统：有真实 DeepSeek 调用、人工审核、建单和反馈链路；不是插件，也不是多智能体或 RAG。
- 跨团队同步：工具提供任务和风险同步能力；个人项目不能证明真实跨团队推进。

## 面试表达
基于现有工单后端完善个人实践原型，使用 AI 辅助开发和调试，接入 DeepSeek 分诊，串联人工确认、工单处理和反馈回查；通过场景验收发现并修复自动更新、详情入口和反馈记录问题。区分原有代码、AI 生成内容与自己实际完成和理解的修改，不声称独立从零开发全部系统。
